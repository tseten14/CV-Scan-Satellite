================================================================================
CV-SCAN-SATELLITE — CODEBASE DOCUMENTATION
================================================================================
Generated for developers maintaining or onboarding to the repository.

This monorepo bundles three web experiences behind one Vite dev server and a
single FastAPI backend:

  Route "/"        — CV-Scan: SAM 3 (and optional YOLO) entrance / building
                     detection on Street View or satellite captures.
  Route "/venues"  — Venue Finder: transit entrances on maps (static CSV +
                     optional backend search API).
  Route "/spatial" — Spatial Visualizer: DuckDB WASM + SQL + MapLibre GeoJSON.

Root package.json delegates to frontend/ (npm run dev, backend, build, test).
Frontend dev server: http://localhost:8080 (Vite). API proxy: /api → :8000.

  • Problem: Manual mapping of entrances and building extent is slow; analysts

  2. Search or click map → pin placed.
  3. Street View mode: fetch street image (or upload / paste image).
  4. Choose engine: SAM 3 (masks/polygons) or YOLO (boxes, faster/smaller model).
  5. Run detection → overlay + optional export (satellite: GeoJSON building points).

SLIDE 6 — AI BACKEND: TWO ENGINES
--------------------------------------------------------------------------------
  • SAM 3 (Meta, Hugging Face): Text-prompted instance segmentation; outputs
    masks → smoothed polygons; default for quality on entrances / buildings.
  • YOLO (Ultralytics): Self-trained YOLOv9-Tiny on doors; bounding boxes
    relabeled entrance (street) / building (satellite); optional where speed or
    ops constraints matter.
  • Single API: POST /detect?mode=streetview|satellite&engine=sam3|yolo
  NOTE: Mention HF_TOKEN gating for SAM 3 — common audience question.

2. BACKEND — main.py (FastAPI APPLICATION)
================================================================================

startup()
  - On server boot, calls load_sam3() once so the first request is faster.
  - Failures are logged; server still starts (SAM routes fail later with a
    clear error).

GET /health
  - Output: {"status": "ok"}. No model load.

GET /streetview-image?lat=&lng=&heading=
  - Uses Google Street View Metadata API (embedded API key in source) to resolve
    pano_id, computes heading from panorama toward the pin, fetches a 640×640
    thumbnail from Google's thumbnail host.
  - Output: JPEG image bytes (image/jpeg), or HTTP 404 if no panorama, 502 on
    upstream/network errors.

GET /entrances?query=&lat_min=&lat_max=&lon_min=&lon_max=
  - Wraps get_entrances() from entrances.py.
  - Output: {"entrances": [ { stationName, source, lat, lon }, ... ]}

GET /entrances/cta?lat_min=&lat_max=&lon_min=&lon_max=
  - Wraps get_cta_entrances().
  - Output: same JSON shape; source is "CTA".

POST /detect
  - multipart/form-data file upload (image).
  - Query: mode = streetview | satellite; engine = sam3 | yolo | yolov9 |
    yolo26 (legacy aliases normalize to yolo).
  - Output (DetectionResult-compatible JSON):
      image_width, image_height, detections[], processing_time_s, engine
    Each detection: id, label, confidence, bbox {xmin,ymin,xmax,ymax},
    optional polygon [[x,y],...] (SAM masks; YOLO uses bbox corners).

CORS
  - Allows localhost:5173, 8080 and 127.0.0.1 variants for browser fetch.

3. BACKEND — entrances.py
================================================================================

Constants
  - DATA_DIR: backend/data/entrances/
  - BOUNDING_FILE: bounding.txt — index of per-city/source .txt CSVs and their
    geographic bounding boxes.
  - DEFAULT_BBOX: unbounded search if no bbox query params.

get_entrances(query, lat_min, lat_max, lon_min, lon_max, score_cutoff=45)
  - Empty/whitespace query → [].
  - Reads bounding.txt, selects sources whose bbox overlaps the request bbox
    (with fallbacks to search all when appropriate).
  - For each source file: filters rows by bbox, fuzzy-matches stationName
    against query via rapidfuzz (token_sort_ratio), score_cutoff default 45.
  - Output: list of dicts { stationName, source, lat, lon }.

get_cta_entrances(lat_min, lat_max, lon_min, lon_max)
  - Reads cta.txt only; defaults bbox to Chicago CTA extents if params omitted.
  - Output: same record shape with source "CTA". No text search.

4. BACKEND — sam3_service.py (SAM 3 PIPELINE)
================================================================================

Public API
----------
load_sam3() -> bool
  - Loads facebook/sam3 via Transformers (Sam3Model, Sam3Processor).
  - Uses HF_TOKEN / HUGGING_FACE_HUB_TOKEN; device from SAM3_DEVICE (cpu/cuda/
    mps/auto). float16 on CUDA only (MPS float16 avoided due to decoder bugs).
  - Optional torch.compile on CUDA if SAM3_TORCH_COMPILE=1.
  - Output: True on success, False on failure (logged).

run_detection(image_bytes, mode="streetview") -> dict
  - Ensures model loaded; runs under _sam3_inference_scope() for thread/GPU
    hygiene.
  - Delegates to _run_detection_inner; returns JSON-compatible dict with
    engine "sam3".

_run_detection_inner(image_bytes, mode, start_time) -> dict
  - **Satellite mode:** resize to max dimension (SAM3_SAT_MAX_DIM, default 640),
    run prompts "building", "roof"; merge labels to "building"; drop huge
    boxes; NMS; scale polygons/bboxes to full image.
  - **Street view mode:** resize to SAM3_STREET_MAX_DIM (default 384); run
    entrance prompts ("door", "building entrance"); optional second pass for
    vehicles if SAM3_VEHICLE_PASS=1; long chain of filters (see below);
    by default collapses to one primary entrance unless SAM3_MULTI_STREET_ENTRANCE=1.
  - Normalizes entrance-like labels to "entrance".
  - Output fields: image_width, image_height, detections, processing_time_s,
    engine "sam3".

Core inference & geometry
-------------------------
_run_inference_pass(...)
  - Batched text-prompt SAM 3 forward; converts masks to polygons via OpenCV
    contours; builds detection dicts with bbox + polygon.

_mask_to_polygon / _mask_to_all_polygons / _contour_to_polygon
  - Raster mask → vector outline in image coordinates.

_clip_polygon_to_bounds
  - Clips polygons to image rectangle.

_generate_tiles
  - (Utility for tiled coverage; satellite path in current code uses a single
    pass at reduced max_dim per _run_detection_inner.)

Post-processing & filtering (street view)
-------------------------------------------
_nms / _iou / _overlap_ratio
  - Non-maximum suppression and overlap helpers.

_cap_per_class
  - Limits how many detections per label class.

_filter_person_building_overlap
  - Reduces person/building mask conflicts.

_filter_google_map_signs / _filter_sign_pole_on_building
  - Heuristics to drop UI-like false positives.

_filter_non_building_doors
  - Removes door-like masks that are unlikely to be façade entrances.

_filter_entrances_on_vehicles / _nms_streetview_split_vehicle
  - Uses vehicle masks (when present) to drop entrances on cars.

_filter_street_entrance_foreground_clutter
  - Sidewalk / near-camera clutter suppression.

_merge_entrance_detections / _merge_sidewalk_detections
  - Merges redundant nearby entrance fragments.

_filter_first_floor_entrances
  - Vertical band filter (configurable via SAM3_STREET_GROUND_DOOR_MIN_Y /
    MAX_Y) to prefer ground-floor façade doors.

_prefer_facade_entrance_cluster / _drop_entrances_when_only_foreground_band
  - Facade-focused selection heuristics.

_drop_entrances_far_below_best_confidence
  - Drops weak detections far below the best score.

_street_entrance_quality_score / _select_single_best_street_entrance
  - Ranks candidates for single-entrance API behavior.

_collapse_api_entrances_to_one
  - Final client-facing collapse when multi-entrance mode is off.

_is_entrance_label
  - Label membership for entrance synonyms.

Runtime tuning
--------------
_get_device, _apply_runtime_footprint, _system_friendly_default
  - Thread caps (OMP/MKL/etc.) for cooler CPU behavior.

_release_accelerator_memory
  - Optional cleanup after inference.

_sam3_inference_scope
  - Context manager around inference.

_env_truthy, _street_vehicle_pass_enabled
  - Feature flags for vehicle pass and multi-entrance output.

Helpers for tensor/box parsing
------------------------------
_tensor_batch_len, _to_float_score, _xyxy_from_box, _min_area
_prepare_mask
  - Low-level SAM output parsing and area checks.

5. BACKEND — yolo_service.py (YOLOV9-TINY DOOR MODEL)
================================================================================

_resolve_yolo_weights_path() -> Path | None
  - YOLO_WEIGHTS env override, else yolo-selftrain/yolov9t.pt, else
    backend/yolov9t.pt.

load_yolo() -> bool
  - Loads weights once with Ultralytics YOLO class.

_bbox_to_polygon(bbox)
  - Axis-aligned bbox → 4-point polygon for API parity with SAM.

_normalize_label(raw)
  - Lowercase/strip class name.

_filter_streetview_door_false_positives(dets, img_w, img_h)
  - Geometry heuristics: drop wide-short boxes (cars), tiny slivers, pedestrians
    in lower frame, etc.

run_yolo_detection(image_bytes, mode="streetview") -> dict
  - **Street view:** upscaled imgsz for small tiles (640–1280, multiple-of-32);
    conf from YOLO_STREET_CONF (default 0.22), relaxed for small images; second
    predict pass if no boxes on small tiles; relabels all classes as "entrance";
    min confidence YOLO_STREET_MIN_CONF; applies _filter_streetview_door_false_positives;
    NMS via _nms from sam3_service; _cap_per_class; keeps top 8 by confidence if
    more than 8.
  - **Satellite:** relabels as "building"; drops boxes > 12% image area; NMS.
  - Output: same shape as SAM (engine "yolo"), polygons are bbox rectangles.

13. CHALLENGES FACED (ENGINEERING & PRODUCT)
================================================================================

These are reflected in README troubleshooting, code comments, and heuristics:

Model access & weight distribution
  - SAM 3 is gated on Hugging Face; users need accounts, access approval, and
    HF_TOKEN. Server preload can fail without taking down the whole API.
  - YOLO weights are not auto-downloaded in-app (avoids brittle SSL/network in
    some environments); operators must place yolov9t.pt (or set YOLO_WEIGHTS).

Performance & thermals
  - SAM 3 is heavy on CPU; default thread caps and reduced street max dimension
    target acceptable laptop behavior. GPU/MPS/CUDA paths exist but have
    different dtype constraints.

Street view domain
  - Glass storefronts, vehicles, pedestrians, and Google Maps UI elements
    create false "entrance" masks; the codebase accumulated many filters
    (_filter_*, NMS, single-best-entrance defaults) to make the API usable.

Satellite domain
  - One building may produce multiple overlapping masks; frontend merges clusters
    to one point per building for map markers and exports.

Low-resolution captures
  - html2canvas map captures can be small; README notes upscaling and backend
    tuning for tiny images. Best results use full-resolution uploads or Street
    View fetches.

API & integration
  - CORS and Vite proxy must align (8080 frontend → 8000 backend via /api).
  - Long detection times require generous client timeouts (8 minutes in
    backendDetection.ts).

Documentation drift
  - README sections may still mention YOLO-World / open-vocabulary flows from an
    earlier iteration; the implemented YOLO path in yolo_service.py is a
    self-trained door detector (yolov9t). Verify behavior against code when
    debugging.

Unused / alternate paths
  - entranceDetection.ts (COCO-SSD) exists as an alternative browser fallback but
    is not imported by the main CV-Scan page (mock path is used on SAM failure).

Spatial WASM
  - DuckDB spatial extension may be unavailable depending on WASM bundle;
    initDuckDB logs a warning and continues.

Security note
  - Google Maps API key is embedded in main.py for Street View metadata/thumbs;
    rotate/restrict keys for production deployments.
